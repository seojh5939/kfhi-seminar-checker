## 1. 요구사항 재정의

본 프로젝트는 약 800명 규모의 기아대책 행사 출입관리를 위한 **Windows 데스크톱 애플리케이션 2종 (QR코드 생성기, QR코드 인식기)** 개발 프로젝트이다. 두 시스템은 오프라인 환경에서 동작하며, 단일 Git 레포지토리(모노레포)로 관리된다.

### 1.1 QR코드 생성기 (Generator)
- **사용 주체 및 환경**: 관리자 PC 1대 (Windows), 오프라인
- **주요 기능**:
  - Excel(.xlsx) 명단 파일 업로드 (관리번호 5자리, 성명, 소속, 직함)
  - 입력값 검증 (관리번호 자릿수/중복, 직함 드롭다운 일치 여부, 소속 공란 여부)
  - AES-256-GCM 암호화 기반 대량 QR 이미지 생성 (800건 기준 3분 이내 목표, 여백 없는 정사각형 PNG)
  - 파일명 규칙: `{관리번호}.png` (소속별 하위 폴더 자동 분류)
  - 매니페스트 CSV(관리번호, 성명, 소속, 직함, 파일명, 생성일시) 생성
  - 생성 이력 관리

### 1.2 QR코드 인식기 (Reader)
- **사용 주체 및 환경**: 출입 지점 PC N대 (Windows), 오프라인
- **주요 기능**:
  - **Step 1 (장소 등록)**: 최초 실행 시 설치 장소명 입력 및 로컬 저장 (PC-장소 1:1 고정). 장소 변경 시 기존 방문기록 CSV 다운로드 강제 적용
  - **Step 2 (QR 스캔)**: 내장/USB 카메라 프레임 스캔 -> AES-256-GCM 복호화 (1초 내외 처리)
  - **Step 3/4 (결과 안내 및 저장)**:
    - 최초 방문: `"{성명} {직함}님 방문을 환영합니다"`
    - 중복 스캔: `"{성명} {직함}님 또 오셨네요 반갑습니다"`
    - 실패: `"등록되지 않았습니다. 스탭을 통해 확인 부탁드립니다"`
    - 스캔 성공 건은 매회 누적하여 로컬 DB/파일에 저장 (성명, 소속, 직함, 방문장소, 방문시간 `YYYY-MM-DD-HH:mm:ss`)
  - **설정 화면**: 방문기록 CSV 추출, 로그 CSV 추출, 버전 정보 표시, 장소 변경

### 1.3 공통 및 형상관리 (Shared / Monorepo)
- **단일 Git 레포지토리 구조**:
  - `/generator`: QR 생성기
  - `/reader`: QR 인식기
  - `/shared`: 공용 암복호화 로직, 데이터 스키마, 상수 정의
  - `/docs`: 문서
  - `/build`: 빌드/배포 스크립트 및 인스톨러 산출물
- **보안**: AES-256-GCM 대칭키 하드코딩 (shared 모듈 내 상수 보유)
- **배포**: 개별 무설치 또는 인스톨러 배포 (자동 업데이트 없음)

## 2. 미확정 사항 및 가정 (Assumptions) 선언

### 2.1 시스템 운영 및 환경 가정
1. **운영체제 환경**: 현장의 모든 PC는 Windows 10 또는 Windows 11 64-bit 환경이다.
2. **네트워크 독립성**: 생성기와 인식기 모두 동작 중 외부 인터넷 연결이 완전히 차단되어도 모든 기능(카메라 스캔, 파일 입출력, 암복호화)이 정상 동작해야 한다.
3. **데이터 수동 취합**: N대의 인식기 데이터는 통합 서버나 네트워크 동기화 없이, 설치 지점별 CSV 추출 후 관리자 엑셀 수동 취합 방식으로 이뤄진다.

### 2.2 기술 스택 관련 미확정 사항
- 데스크톱 프레임워크 선택 (Electron, .NET/WPF, Tauri, Python/PySide 등)
- 로컬 영속화 스토리지 선택 (SQLite, 로컬 JSON/CSV DB 등)
- 모노레포 패키지 매니저 및 툴체인 선택

## 3. 위험 요소 분석 (Risk Factors)

| 위험 요소 | Level | Impact | 내용 및 대책 방향 |
|---|---|---|---|
| **카메라 호환성** | High | 기능 | 노특북 내장 웹캠 및 다양한 USB 외장 카메라 장치 인식 및 오프라인 영상 스트림 프레임 캡처 안정성 확보 필요 |
| **인식/복호화 성능** | Medium | 성능 | 스캔 화면에서 연속 프레임 처리 시 CPU 점유율 증가 방지 및 1초 이내 복호화/화면 반응 속도 유지 |
| **방문기록 데이터 유실** | High | 운영 | 인식기 비정상 종료(전원 꺼짐 등) 시 로컬 DB 트랜잭션 손상 방지 및 장소 변경 시 백업 강제 흐름 검증 |
| **한글 인코딩 깨짐** | Low | 기능 | Windows Excel 및 CSV 내보내기 시 한글 깨짐 방지 (BOM 파싱/처리 고려) |

## 4. 기술 선택지 후보 나열 (비교·추천 금지 원칙 준수)

> **규칙에 따라 특정 기술을 추천하거나 선택하지 않으며, 검토 가능한 후보군만 나열합니다.**

- **후보 A: Electron + React / Vue (Node.js)**
  - HTML/CSS 기반 UI 구성, cross-platform 데스크톱 런타임, node-webcam / HTML5 getUserMedia 사용
- **후보 B: .NET / WPF 또는 WinUI 3 (C#)**
  - Windows 네이티브 런타임, System.Security.Cryptography 및 OpenCvSharp / MediaFoundation 사용
- **후보 C: Tauri + React / Vue (Rust + Webview2)**
  - 경량 데스크톱 런타임, Rust 기반 보안/성능 모듈 및 HTML5 Webview2 기반 UI
- **후보 D: Python + PySide6 / PyQt6 (Python)**
  - OpenCV(cv2) 기반 카메라 제어 및 PySide/PyQt 기반 UI, PyInstaller 패키징
